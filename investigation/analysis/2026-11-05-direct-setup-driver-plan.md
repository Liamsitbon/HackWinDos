# Direct Setup and J413 driver completion work

Intent: the operator confirms Windows Setup for now, with bootloader and installer on the same volume instead of broad discovery. Prior native trial EXP037 failed USB enumeration and no newer candidate has been launched. Internal Asahi/UEFI was deleted; no partition change is authorized by this verification work. Current media is the recorded SanDisk with M2BOOT FAT32 and WININSTALL exFAT. Complete installer data exceeds the 2GB FAT partition; a truly single-volume FAT bundle needs split install.wim and sufficient capacity, not just copying boot.wim.

Source-first inspection: fresh analysis/2026-11-05-direct-setup-live-resources.json and current disk/USB traces; Asahi asahi t8112.dtsi, drivers/soc/apple/dockchannel.c and drivers/hid/dockchannel-hid/dockchannel-hid.c; pinned m1n1 rust/src/chainload.rs, src/payload.c, src/chainload.c, src/hv_bootstrap.c and J413 mapping/IRQ owners; Mu J413 DSDT, WindowsAutoBootDxe, FAT/PartitionDxe headers and BDS ownership; official Microsoft VHF, VhfCreate/VhfStart/VhfDelete, WdfWorkItemFlush/WdfMemoryCreate and BCDBoot/WinPE architecture; last assisted J313 and standalone J413 contracts in EXP028-040. Asahi osinstall.py embeds chosen.asahi,efi-system-partition, but this is a kboot variable, not a verified preserved ADT property through the project's early nested bootstrap. Do not guess its presence in Mu or use a random filesystem anchor.

Direct policy: select an explicitly configured GPT partition unique GUID and only its fixed ARM64 fallback path; compare partition identity before any filesystem open. Reject zero, malformed and duplicate target identities, wrong architectures and incomplete media. The installation/package script must bind that same GUID and place m1n1/boot.bin, EFI loader/BCD, boot.wim, boot.sdi and complete Setup source together. Retain standard BDS LoadImage security. This is target identity resolution, not arbitrary EFI discovery. Build/install manifests must record the GUID. The chosen final physical target remains pending the operator's internal-versus-USB preference. No hardware setup/register change is justified by this policy.

Driver ownership: Windows inbox USBXHCI/USBHUB3/USBSTOR/HIDUSB/storage/basic display provide standard class drivers only after Mu/m1n1 expose correct ACPI/DMA/IRQ contracts. Custom M2 DockChannel needs separate IRQ/config/data blocks, MTP helper firmware, DART, GPIO and discovery/report semantics. Current Windows wrapper maps first resource (IRQ block) as FIFO and ignores additional required regions. Current GPU wrapper's J313 broker/resource expectations conflict with J413 ACPI; do not remove those checks to claim acceleration. Wi-Fi/Bluetooth/audio/PEP have no complete Windows implementations in this checkout. No invented register or IRQ mapping.

Confirmed software defects for individual regressions: VHF initialization loses create/start errors and marks both devices started even on failure; D0Entry discards that error; completed stream frames are never consumed/reset before feeding a concatenated next frame. Correct these logic contracts with actual-source host harnesses, not a claim that missing firmware/DMA adapters are implemented. Add the required VhfKm link dependency in the WDK project. Do not publish a fabricated Precision Touchpad capability claim.

Packaging defect: package-m2-drivers.sh declares a ready package and successful installation when it copied only INF source metadata, and includes the J313 SPI driver for M2. Require real ARM64 SYS/CAT content, exact hashes and a J413 qualification record before enabling a deployable driver; otherwise report missing binaries/contracts. Never label source-only directories as installed drivers.

Smallest falsifiable checks: C harnesses show each VHF failure leaves no partial handles and propagates status; two concatenated frames deliver two distinct sequence values; direct boot opens only the configured partition; bundle manifests verify every copied/split source; software/firmware build and image identity pass. Physical checkpoint remains native storage/target resolution then standard loader entry. Driver completion separately requires transport/IRQ/DMA/restart and real input/GPU tests on J413. Recovery remains preserved manifested artifacts and macOS; do not install experimental bytes or reboot during this work.
