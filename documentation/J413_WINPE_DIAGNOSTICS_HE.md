# מצב האתחול ואיסוף מידע על אחסון וקלט

התמונות IMG_6329/6330/6331 מאשרות שבניסוי EXP-20261105-J413-054 עלה
Windows 11 Setup. הוא מציג הודעת missing media driver. ההודעה אינה מזהה
איזה התקן או דרייבר נכשל. הקושחה שהגיעה לשלב הזה נשמרה, SHA256:
`639d558d3e1abe42024df8edc298f12e283cc87906920851858a76e66db59cc9`.

המקלדת והמשטח המובנים עדיין דורשים השלמת DockChannel/MTP. חבילת SYS/INF/CAT
הקיימת היא ניסיונית ואינה דרייבר אחסון. אין כרגע חבילה שהוכחה כפותרת את מסך
המדיה. הניסיון הראשון של העכבר החיצוני היה מחובר ל־iPad ואינו בדיקת USB תקפה.
בניסיון המאוחר יותר דווח שהעכבר לא הגיב והלדים לא נדלקו בשתי הכניסות.
ב־macOS אותו עכבר E-Signal מזוהה מאחורי רכזת GenesysLogic; זה אינו אישור
לתקינות ה־USB בקושחה או ב־Windows. מצב מתח VBUS לא נמדד.

קודם אפשר לקרוא את יומן הקושחה הקיים ללא החלפת קבצים. מתוך תיקיית הפרויקט:

```sh
bash scripts/collect-j413-usb.command
```

יש להריץ את המשגר כמשתמש הרגיל, בלי sudo בתחילת הפקודה. הוא מבקש
אימות מנהל בטרמינל ורק לאחר מכן מפעיל את האוסף עם sudo. הפלט נשמר
בהרשאות פרטיות של המשתמש תחת `.local/usb-evidence`, עם `LATEST.json`
ומזהה SHA256. כך אפשר לקרוא אותו ישירות מהפרויקט בלי להדביק את הפלט
בצ'אט. בקשת הסיסמה מתרחשת לפני לכידת הפלט; הסיסמה אינה נשמרת בקובץ.
המידע נשאר במחשב ולא נשלח ברשת. כשל באוסף נשמר ומוחזר כקוד יציאה.

פקודת האוסף הישירה עדיין זמינה:

```sh
sudo /usr/bin/python3 scripts/install-j413-winpe-diagnostics.py --collect-only
```

נדרשת סיסמת מנהל מקומית לגישה למחיצת EFI. הסקריפט בודק את ה־GUID,
מבקש עיגון לקריאה בלבד ואוסף את `m1n1/j413uefi.log` אם קיים. בהרצת הבעלים
EXP-20261105T214802Z-J413-WINPE-4c24cdc4 גם העיגון המורשה נכשל.
לכן הגרסה המעודכנת יכולה לקרוא ישירות את אותם שני קובצי FAT32 קצרים:
`m1n1/boot.bin` לאימות גרסת הקושחה, ו־`m1n1/j413uefi.log` לאיסוף היומן.
התקן המחיצה נפתח לקריאה בלבד, לפי ה־GUID והגודל שנמדדו, והקריאות מיושרות
לגודל הבלוק. אין ממשק כתיבה או תיקון בדיסק. טבלת הקצאה לא עקבית, שרשרת
מעגלית, גאומטריה חריגה או קושחה אחרת גורמות לעצירה עם הסבר.
לא נדרשת עוד הפעלה מחדש לצורך קריאת היומן הקיים. עדיין לא הוכח מה גרם
לכשל העיגון. אם גם האיסוף הישיר נעצר, פרטי השגיאה מוצגים ונשמרים בתיקיית
הראיות; אין להתקין שוב את Asahi בגלל כשל איסוף.

להמשך אבחון מתוך WinPE הוכנה בנייה נפרדת, `dist/j413-winpe-diagnostics`.
להתקנתה לאחר אימות מקומי:

```sh
sudo /usr/bin/python3 scripts/install-j413-winpe-diagnostics.py
```

אפשר להתקין דרך אותו משגר ששומר פלט נגיש בפרויקט:

```sh
bash scripts/collect-j413-usb.command --install-diagnostics
```

במצב המפורש הזה, אם שירות העיגון הרגיל נכשל, מותר לסקריפט לנסות את
כלי FAT של macOS ישירות על אותה מחיצה שנבדקה לפי GUID, בתיקיית עיגון
פרטית. אין תיקון מערכת קבצים. אם גם הכלי הזה מסרב, הפעולה נעצרת והודעתו
המלאה נשמרת בפלט הנגיש. רק לאחר עיגון מוצלח, אימות המדיה וגיבוי מתבצעת
החלפת WIM. בסיום העיגון הפרטי נסגר. אין להפעיל את המק מחדש אם המשגר
מדווח שגיאה; אפשר לקרוא את הפלט מתוך הפרויקט.

הסקריפט מאמת את המדיה המקורית ושומר גיבוי מלא של `boot.wim` ורשומות המדיה,
ואז מחליף רק את WIM האתחול ומוסיף סמן אבחון. הקושחה, דרייברי Windows
וקובצי install.swm נשארים ללא שינוי. אין התקנת Windows אוטומטית או הפעלה
מחדש. פקודת השחזור המדויקת מודפסת בסיום; היא משחזרת גם את רשומות המדיה.

בהפעלה אבחונית רגילה נפתח Setup המקורי. לאחר כ־30 שניות מרגע הפעלת
מעטפת WinPE ואיסוף המידע אמור להיפתח חלון דוח שמתחיל בפרטי USB, ממשיך
לתקלות התקנים, HID ודיסקים. העמודים מתחלפים אוטומטית כל 12 שניות וחוזרים
על עצמם; אין צורך בעכבר, מקלדת או גלילה. יש לצלם את עמודי USB והתקלות.
הדוח המלא נשמר גם ב־RAM. אם Windows רואה מחיצה אחת בלבד בעלת סמן ה־GUID
המדויק, נשמרים בה גם יומני PnP ו־Setup בתיקייה חדשה בתוך `J413Setup/Logs`.
כאשר המדיה אינה נגישה, הדוח נשאר ב־RAM ובחלון בלבד.

באבחון הראשון, EXP-20261106-J413-060, נפתח בפועל Notepad ונראו דיסק
פנימי ובקר NVMe במצב Started. מחיצת המתקין הייתה Hidden ללא אות כונן,
ולכן חיפוש הסמן לפי אותיות לא מצא אותה והדוח לא נשמר שם. פרטי USB היו
מחוץ לתמונה והקלט לא עבד. החלון האוטומטי מתקן את התלות בגלילה; הוא טרם
נצפה בחומרה, ואינו דרייבר לעכבר או תיקון מוכח ל־USB/מדיה. מדיניות העיגון
נשארת כפי שהייתה. אין טעינת דרייברים, איפוסי התקנים או שינוי מחיצות ואבטחה.

אפשר לעדכן ישירות את WIM האבחון הראשון שצולם: המתקין מקבל רק את
ה־SHA-256 המפורש שלו ורשומות מדיה תואמות, ושומר גיבוי מלא לפני החלפה.
אין צורך לשחזר אותו קודם ל־WIM המקורי. בדיקות חלוקת העמודים עם
ASan/UBSan ובדיקות הגיבוי, השחזור וזהות המחיצה עברו; נבדקו ARM64,
הבתים שנוספו ותקינות WIM. לא הורצה שוב חבילת הבדיקות הרחבה.
